# 聚合 API

这是一个面向 OpenAI 兼容客户端的多来源 API 网关示例，包含 Docker 部署、来源优先级、会话保持、故障转移、来源/模型级熔断、官方额度预留和本地控制面板。

## 主要功能

- 聚合两个官方 OAuth 账号与多个兼容 API 来源，按优先级故障转移。
- 保持会话来源；会话使用中转站时，可在下一次请求优先尝试恢复的官方来源。
- 区分来源故障、特定模型无渠道、余额不足、授权失效及限流，自动退避与恢复验证。
- 官方额度默认预留 10%，短窗口及周窗口独立判断，查询未知时保护性跳过。
- 手动同步上游模型目录，保留上游原名；支持来源前缀定向请求。
- 中文深浅色控制面板，支持排序、启停、测试、恢复检查与请求元数据日志。
- 日志不记录请求/回复正文和凭据，Docker 默认仅向本机开放端口。

首次部署请完整阅读部署手册。本项目不会替你创建供应商账号或附带任何可用的账号、密钥和订阅。

项目以 **AGPL-3.0-or-later** 发布，详见 [LICENSE](LICENSE)。

AI Agent 请先阅读 [AGENT_DEPLOY.md](AGENT_DEPLOY.md)。首次初始化由 Compose 的 init 服务完成。面板支持管理已有来源；新增来源需要编辑本地 upstreams.json，再按部署文档更新配置，不能只在面板中添加。

## 开源发行版边界

此目录不包含真实 API Key、OAuth 凭据、请求日志、额度数据、运行状态或本机网络配置。`docker/cli-proxy-api` 也未随项目发布，因为它是外部组件，需按其自己的许可和再分发条款单独获取。

使用前请将兼容的 CLIProxyAPI 可执行文件放入 `docker/cli-proxy-api`，并根据 `private/*.example.json` 创建运行配置。真实的第三方供应商地址和 Key 只应保存在本地 `private/` 中。

外部网关适配基线为 CLIProxyAPI v8.0.31。源码包不包含网关二进制，需要单独获取、校验并保留其许可声明。

## 许可和第三方组件

本仓库中的控制器、路由器、网页和编排文件采用 AGPL-3.0-or-later。外部网关、供应商 SDK、模型服务和图标等组件仍受各自许可约束；发布整合版本时请保留对应版权和许可声明。

## 安全发布检查

发布前请确认：

- `private/`、`reports/`、`runtime/` 和 SQLite 文件没有进入 Git；
- 没有提交 API Key、OAuth token、Cookie、设备码或真实上游 URL；
- 已为客户端 Key 和管理 Key 生成不同的随机值；
- 控制面板仍只绑定本机地址，是否开放 API 到局域网由部署者自行配置；
- 外部 CLIProxyAPI 的许可允许当前分发方式。

## 运行方式

复制 `compose.example.yaml` 为 `compose.yaml`，按注释设置端口和数据目录，然后执行：

```powershell
docker compose build
docker compose up -d
```

控制器和路由器代码不访问用户的 Codex 配置目录。首次部署后，打开控制面板完成来源配置和 OAuth 登录。
