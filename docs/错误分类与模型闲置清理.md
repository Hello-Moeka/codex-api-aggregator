# 错误分类与模型闲置清理

本说明描述 2026-10-17 更新后的实现。供应商可能采用不同版本或私有修改，不能保证覆盖所有自定义错误。

## 分类规则

路由先解析结构化 `error.code`、`error.type`，支持普通 HTTP JSON、HTTP 200 中的失败 JSON、SSE `error`、`response.failed/incomplete`，以及 `error.message` 中最多四层 JSON/SSE 包装。最后才使用 HTTP 状态兜底。

| 错误 | 处理 |
|---|---|
| `context_length_exceeded`、`context_too_large`、真正参数错误 | 停止当前请求，不累计来源故障 |
| `prompt_blocked`、`sensitive_words_detected`、内容/安全策略拒绝 | 停止当前请求，不通过其他来源重试 |
| `previous_response_not_found` | 返回 409，要求完整历史，不跨来源续接 |
| `model_not_found`、`get_channel_failed`、`channel:no_available_key`、模型映射/定价错误 | 当前来源的当前模型不可用，允许转其他来源 |
| `insufficient_quota`、`insufficient_user_quota`、`pre_consume_token_quota_failed` | 当前模型不可用，不作为实际余额依据 |
| 官方明确额度限制 | 进入官方额度等待；支持绝对重置时间和 `resets_in_seconds`，仍需额度查询确认 |
| `rate_limit_exceeded`、`slow_down`、`server_is_overloaded` | 按限流冷却，尊重 `Retry-After`，输出前允许切换 |
| 明确认证失败 | 当前来源凭据等待修复，允许切换 |
| 明确模型 `permission_denied` | 当前来源的当前模型隔离，允许切换 |
| 未知 403、地区/访问限制 | 按来源访问受限处理，不自动认定仅一个模型有问题 |
| `upstream_unavailable`、`do_request_failed`、渠道超时及返回异常 | 上游临时故障，沿用来源级失败规则，输出前允许切换 |

一旦向客户端输出内容或工具事件，始终不跨来源重放。来源前缀和 `previous_response_id` 限制继续生效。

## 脱敏诊断

请求尝试只保存 `outer_http`、外层 `code/type` 和解析后的内层 `code/type`，不保存原始错误消息、请求正文或凭据。流内错误保留实际 HTTP 200 传输状态，最终响应状态单独记录。

## 模型错误闲置清理

同一来源的同一模型连续 3600 秒没有真实客户端业务尝试后，自动清除 `model_unavailable`、`permission_denied` 及兼容模型等待错误和滚动失败计数。恢复探测、手动测试和余额查询不刷新计时；正在执行的恢复探测不会被删除。

清理不等于模型验证恢复，不直接赋予会话回迁资格。下一次真实请求可重新尝试，失败会重新记录错误。来源级熔断、官方额度预留、余额状态和历史日志不受影响。

## 验证

九套模拟与展示回归共 251 项通过：路由 26、额度预留 21、恢复计时 8、回迁 11、审计 23、修复集成 16、模型闲置 15、错误分类 94、前端展示 37。所有测试使用临时状态和本地模拟上游，没有调用真实供应商。
